## Audit: `@bitCast` (0.17: logical bits; extern struct/union rejected)

335 `@bitCast` calls in `src` (excluding uucode_lib).

1. **Extern struct/union casts** are compile errors now, so the compiler found all of them (8). Each was memory
   punning and now uses `bun.memCast(To, value)` (`std.mem.bytesToValue(To, &std.mem.toBytes(value))`): the same
   bytes, so the same result:
   `src/install_types/SemverString.zig` (3 sites → `initExternal` + `ptr()`), `src/bun.zig` (`zero`),
   `src/runtime/socket/SocketAddress.zig:434`, `src/runtime/timer/Timer.zig:647`, `src/runtime/webcore/Sink.zig:231,235`,
   `src/sourcemap/InternalSourceMap.zig:155`. `NativeBrotli.zig:136` (zeroing an extern union) became `.{ .e = 0 }`.
2. **Arrays and vectors** can change silently, but only when element types have padding bits (logical size <
   memory size: `bool` in arrays, `u7`, `u24`, packed structs that aren't byte multiples), or on big-endian targets.
   For whole-byte elements on a little-endian host (zun is Linux x86_64/arm64, both little-endian) the logical-bit
   concatenation is the same as the memory layout. The 124 array/vector sites (found by
   `bitcast-table` classification, then read) fall into three groups, all **ok**:
   - **`[N]u8` ↔ integer / `[N]u8`** (72): whole bytes, LE. E.g. `InternalSourceMap.zig:134-150,316-318,748-761,810,811,908-910`,
     `Chunk.zig:236-238`, `immutable.zig:102,939-955,1072-1092`, `unicode.zig:473-534,719-767`, `websocket.zig:80,84`,
     `SocketAddress.zig:140,285,582,605`, `BlockList.zig:147,148,245`, `node_os.zig:617,756`, `process.zig:945,976`,
     `bzrt_compat.zig:562,590`, `url.zig:329`, `paths.zig:403,404`, `resolve_path.zig:56`, `StaticHashMap.zig:396,397`,
     `logger.zig:1290`, `base.zig:203`, `SemverString.zig:376,387`, `InternalState.zig:142`, `websocket_client.zig:991`,
     `fs.zig:881`, `dir_iterator.zig:98`, `BunObject.zig:1462`, `Blob.zig:501`, `SmolStr.zig:181` (packed ↔ packed).
   - **`@Vector(N, bool)` → `@Vector(N, u1)` → integer** (48): one logical bit per lane, lane 0 = bit 0, which is
     what the old code relied on. `lexer.zig:3346-3352`, `immutable.zig:842,1267-1281,1360,1361,1745`,
     `visible.zig:677,735,759,991`, `escapeHTML.zig:170-174,228-232,421-426,500-505`.
     (Probe: `migration-017.zig` "@bitCast on byte arrays and bool vectors".)
   - **`@Vector(N, u8|u16)` ↔ bytes** (4): `immutable.zig:1520`, `unicode.zig:511,757,895`.
3. The other ~211 are integer ↔ integer, float ↔ integer, enum/packed ↔ integer: defined as before.

**Finding: no silent `@bitCast` change on the supported targets.** Big-endian targets are out of scope (Linux
x86_64/arm64 only); the byte-array casts would need `std.mem.readInt`-style code there.

## Open items

  it. Moving to the `translate_c` package needs `zig fetch` of `codeberg.org/ziglang/translate-c#zig-0.17.x`
  plus a `build.zig.zon`, and a check that `scripts/build/zig.ts` passes the right cache to the fetch.
- Deprecated-but-working APIs left in place: `std.meta.fieldNames`, `getLast`/`getLastOrNull` on std lists
  (`--report` lists them), old `OptimizeMode` decls inside std. They become errors in 0.18.
- The compat helpers (`bun.meta.fieldsOf` & co, `bun.allocators.stackFallback`) are a bridge. New code should use
  the struct-of-arrays `@typeInfo` and `std.heap.BufferFirstAllocator` directly (see `myers_diff.zig`).
- `build016.zig` keeps its old name. 0.17's configure cache ignores `--build-file`, so run it with its own
  `--cache-dir` (see `docs/zig/lessons.md`).

## What changed in 0.17, and why (for the owner)

**`@typeInfo` became struct-of-arrays.** In 0.16, `@typeInfo(T).@"struct".fields` was a slice of
`StructField { name, type, default_value_ptr, is_comptime, alignment }`. In 0.17 it is three parallel slices:
`field_names`, `field_types`, `field_attrs`. The same happened to enums (`field_names`/`field_values`), unions,
`decls` → `decl_names`, and function params (`param_types`/`param_attrs`). Pointer flags moved into
`attrs.@"const"`, `attrs.@"align"`, …, which is exactly the struct `@Pointer(size, attrs, child, sentinel)` takes.
So `var a = info.attrs; a.@"const" = true; @Pointer(info.size, a, info.child, null)` replaces rebuilding the
attrs field by field (see `bun.span`/`AddConst`). Why: the compiler builds these at comptime, and parallel arrays
are cheaper to make than arrays of big structs, and match what the `@Struct`/`@Union` builtins (new in 0.16) take.
Bun's 250 reflection sites go through `bun.meta.fieldsOf(info)` for now, which rebuilds the old view. Note that it is
an `inline fn` whose body is a `comptime` block: a *non*-inline function returning a slice of structs that contain
`type` gives a runtime-known pointer at the call site, and reading `.type` from it fails.

**`@bitCast` means "same logical bits", not "same memory".** For integers and packed types nothing changed.
For arrays and vectors the bits are concatenated element by element, starting at element 0's least-significant bit.
On little-endian machines, for byte-sized elements, that is the same as memory order. That's why the 124 array/vector
casts are fine here. `extern struct` has no logical bit representation (it has padding and a C layout), so casting it
is now an error. To reinterpret memory, say so: `@ptrCast` to a pointer, or `bun.memCast` (copy bytes).

**`@hasDecl` only sees `pub`.** 0.16 also saw private decls when the call was in the same file. That made the answer
depend on *where* you asked. Now it depends only on the type. The risk is dispatch tables (`visitExpr.zig`): if a
private handler existed, it would silently stop being called. Nothing in zun hit this.

**`**` (array repetition) is gone.** `[_]u8{0} ** 16` becomes `@splat(0)` (the result type gives the length), and a
repeated string becomes a comptime loop (`bun.strings.repeatComptime`). The tokenizer no longer has a `**` token, so
the error is the odd "binary operator '*' has whitespace on one side".

**Allocators take the buffer from the caller.** `std.heap.stackFallback(N, a)` returned a struct that *contained* the
N-byte buffer, and `.get()` had to be called exactly once because it patched internal pointers. `BufferFirstAllocator`
borrows a buffer you own (`var buf: [N]u8 = undefined; var bfa: std.heap.BufferFirstAllocator = .init(&buf, a);
bfa.allocator()`), like every other std API that needs memory. `myers_diff.zig` shows the new form.

**`ArrayList` grew a safety lock.** `pointer_stability: debug.SafetyLock` asserts that nothing grows the list while
someone holds element pointers (`lockPointers`). It has no default value, so struct literals must spell it out.
Prefer `.empty`, `initCapacity` or `fromOwnedSlice` over literals.

**Build system.** `build.zig` now runs in a separate "configurer" process and its output is cached; the build runner
("maker") is prebuilt. Visible effects here: `zig build` lost `--global-cache-dir`/`--zig-lib-dir` (use
`ZIG_GLOBAL_CACHE_DIR`; `--zig-lib=` exists but must be the first argument), `b.pathFromRoot` → `b.root.joinString`,
`OptimizeMode` → `std.lang.Optimize` with `.debug/.safe/.fast/.small` (`-Doptimize=Debug` still parses), and the
configure cache does not include the `--build-file` path.
